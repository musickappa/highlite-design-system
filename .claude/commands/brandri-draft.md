# /brandri-draft

**執筆はClaude Code自身が行う（Anthropic API課金なし）。**
**現在の運用：キーワード記事（経営者トラック）に集中。週1本。**

**いきなり書かない。いきなりSlackに出さない。**
構成案をこのチャットで壁打ちし、OKが出てから執筆する。
本文もこのチャットで確認を取ってから push → Slack 投稿する。

---

## 全体フロー

```
0. テーマを受け取る（指示されたテーマ／なければ keyword-progress.md の次）
1. 構成案を提示する   ← トレンド・構成・参考記事・Highliteの見解
2. レビューを受けて直す   ← OKが出るまで繰り返す
3. 執筆し、本文をチャットで提示する
4. レビューを受けて直す   ← OKが出るまで繰り返す
5. OKが出たら push → Slack へ post
6. 以後は Slack 上のレビュー → /brandri-sync /brandri-resolve /brandri-publish の既存フロー
```

ステップ1・3の提示は、必ずユーザーの返答を待つ。
「OK」「Slackに出して」等の明示がない限り、ステップ5に進まない。

---

## 手順

### 0. 規範とテーマを読む

- `.claude/agents/brandri-writer-executive.md` ← 執筆規範。**必ず読む**
- `marketing/kutouten-rules.md` ← 句読点ルール
- `marketing/keyword-progress.md` ← 消化管理表
- `marketing/branding_seo_keywords_50.md` ← キーワード全体像
- `highlite-ai-harness/skills/_shared/brand-voice.md` / `glossary.md`

テーマの決め方：
- ユーザーがテーマ（キーワード・論点）を指定したらそれに従う
- 指定がなければ `keyword-progress.md` の上から status が `未着手` のものを提案する。
  第1クラスタ（インナーブランディング）→ 第2クラスタ（リブランディング）→ 急伸中の4語、の順

status の更新は、構成案にOKが出て執筆に入る時点で `執筆中` にする。

### 1. 構成案を提示する（壁打ち・1回目）

以下をひとつのメッセージにまとめて出す。長くしすぎない（読んで5分以内）。

1. **痛みの仮説** — そのテーマで検索する経営者は何に困っているか。1〜2文
2. **最近のトレンド** — テーマに関わる直近の動き。`marketing/articles/` の日次サマリを当たり、
   足りなければ web-research スキルで裏取りする。出典URL付きで2〜4点
3. **参考記事** — 執筆時に参照する外部記事・一次情報。URL付きで2〜4本。
   実在確認できたものだけ載せる
4. **記事の構成** — title案（2〜3案）、lead の一文、01〜04 各章の見出しと要旨（各1〜2行）、
   pullquote案、takeaways案
5. **Highliteの見解** — `brand-voice.md` の「事業に余白を」「見た目の手前に判断の一貫性」を踏まえ、
   この記事でどこに立つか。1段落
6. **既存記事との重複チェック** — 前後の記事（drafts / scheduled）と論点が被っていないか

提示したら、ユーザーのレビューを待つ。

### 2. 構成案を直す

指摘された点だけ直して再提示する。指摘されていない箇所は勝手に変えない。
曖昧な指摘は、解釈せずに確認する。OKが出るまで繰り返す。

### 3. 執筆する

OKの出た構成案に沿って、4章構成で書く。

| 章 | 役割 | 字数 |
|---|---|---|
| lead | この記事が誰の・どんな困りごとを扱うかを最初の一文で示す。**ブランディング不使用** | 80〜120字 |
| 01 症状 | 痛みの言語化。「うちのことだ」と思わせる。**説明で書く。場面描写にしない** | 400〜500字 |
| 02 構造 | なぜ起きるか。**まだブランディングと言わない** | 450〜550字 |
| 03 解の名前 | **ここで初めて**「それをブランディングと呼ぶ」 | 450〜550字 |
| 04 明日の一歩 | 実務の初手＋内部導線 | 350〜450字 |

**全体1,800〜2,400字。** 1段落140〜170字、一文50字前後、読点1〜2個。

書けたら、`marketing/articles/brandri/drafts/YYYY-MM-DD-{slug}.md` に保存し、
本文全文をチャットにも貼ってレビューを求める。

### 4. 本文を直す

指摘された点だけ直す。OKが出るまで繰り返す。

### 5. 必ず守ること（執筆・修正のたびに確認）

- **タイトルは痛み語＋題材。** キーワードをそのまま入れてよい。何の記事か一目で分かること
- **lead・01・02 に「ブランディング」を出さない**（本文では03で初出。タイトルは例外）
- **小説にしない。** 台詞→反応の語り／情景描写／独白の書き出し／時系列の場面進行は禁止
- **句読点。** 一文約50字、読点1〜2個。読点3つ以上・80字超の文は分ける
- 禁止語を使わない：世界観／トンマナ／クリエイティブ／アートディレクション／
  パーパス／ナラティブ／エンゲージメント／バズる／認知度アップ／フォロワー／映え／
  おしゃれ・かっこいい・素敵／デザイン思考／DX／イノベーション
- 「リブランディング」は**見出し禁止**（本文では「作り直す」「定義し直す」）
- 英字の全大文字を使わない（頭字語のみ例外）
- 実在確認できない固有名詞・数値・引用を書かない

### 6. front matter

```yaml
title: （痛み語＋題材の見出し）
cat: 経営          # 経営/定義論/採用/インナー/計測/フェーズ別/運用
target_reader:
  - executive      # ← 必須。しきい値判定に使われる
slug: inner-branding
keyword: インナーブランディング
related:           # 2〜3本
  - t: 診断
    href: index.html#diagnostic
  - t: ブランドとは
    href: basics/what-is-brand.html
sources:
  - key: highlite-inner-branding
    title: 「インナーブランディング」をめぐる編集ノート
    author: Highlite 編集部
    year: 2026
    type: 編
```

外部記事を参照した場合は、その出典も `sources` に加える。

### 7. OKが出たら push してから post（順序厳守）

**ユーザーの明示的なOKがあるまで実行しない。**

```
git add marketing && git commit -m "brandri: draft" && git push
python -m scripts.brandri.post marketing/articles/brandri/drafts/YYYY-MM-DD-{slug}.md
```

push 前に post すると、Slackの「本文を読む」リンクが404になる。
post 後、`keyword-progress.md` の status を `レビュー中` にして再度 commit / push する。

## トレンド記事を書きたい場合

デザイナートラックの規範に切り替える：`.claude/agents/brandri-writer-designer.md`
ネタ源は `marketing/articles/` の日次サマリ。
**禁止語が逆転している**（デザイン用語が解禁）ので注意。
front matter は `target_reader: ["designer"]`。
壁打ち→執筆→本人OK→Slack の流れは同じ。
